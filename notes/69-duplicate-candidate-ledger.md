# 入档了两个候选，为什么不一定探索了两个不同设计

生成尝试、评价事件和不同程序是三个计数单位。代理搜索可以再次生成同一段代码；保留两次尝试有助于审计成本，但不能仅因档案多了两行就宣称发现了两个新设计。

## 固定ADAS如何追加档案

原search在评价完成后给next_solution写入fitness和generation，再直接archive.append。这个位置没有先比较已有代码或对候选去重。是否真的产生重复，应检查具体运行，不能只由这条结构条件推断论文重复率。

本地构造两代，初始种子已有fitness；全部元生成桩均返回相同name和完全相同code，评价桩每次返回[1,0]，debug_max=1。原search在临时档案中实际保存：

| 事件 | 代码 | generation | 教学评价结果 |
| --- | --- | ---: | --- |
| 第一代入档 | fixed candidate code | 1 | [1,0] |
| 第二代入档 | fixed candidate code | 2 | [1,0] |

新入档记录2条，评价调用2次，新增记录中按代码字节去重只有1种。两条代码的SHA256相同；没有执行这段教学字符串，更没有用重复文本模拟独立模型发现。

## 去重键说明的边界

代码内容摘要能识别字节完全相同的版本，不能保证识别语义相同而写法不同的程序。反过来，同一代码在不同数据、模型、状态或参数下运行，也不是同一个完整实验条件。记录中应把代码身份与评价协议分开，不能只用其中一个替代全部身份。

重复评价可能是有意估计随机波动，并不天然是浪费或错误。协议应说明它是重复测量，还是一次本来要求新结构的搜索机会；两种情形的费用都已发生，但“不同设计数”的报告方式不同。若去重后跳过调用，也不能凭空给该次记录填入新测量分数。

## 同时报告三种数量

按尝试编号保存完整历史，再派生生成尝试数、实际评价次数、不同代码数与重复测量数。评价结果继续绑定具体代码和协议；不能删除重复记录后把已经发生的成本一起抹掉。真正的架构新颖性需要定义结构等价关系，单靠SHA256数量不足以证明。

练习：同一代码生成3次，分别在两个数据版本上评价，代码摘要只有1个，是否只发生1次实验？答案：不能；代码种类数、评价事件数与协议种类数应分别核对。
