# 四位随机ID，为什么不能保证代理身份唯一

随机字符串可以降低重名概率，但没有冲突检测就不等于唯一身份。若系统还把这段字符串用于标注“这是你自己说的”，碰撞会影响消息归属，而不只是日志看起来相似。

## 固定ADAS中的身份字符串

utils.random_id默认从大小写字母和数字中抽4个字符，共62⁴=14,776,336种。LLMAgentBase初始化将它保存为id，__repr__返回agent_name加id。generate_prompt若发现输入Info.author等于自己的repr，会追加 `(yourself)` 标记。原位置没有维护已用ID集合。

因此要区分ID碰撞和完整身份字符串碰撞：两个不同agent_name即使ID相同，repr仍不同；下面的归属问题要求名字也相同。

## 独立均匀假设下的碰撞概率

同名的n个实例若各自独立均匀生成四位ID，令M=62⁴。第i+1个ID避开此前i个不同值的概率为1-i/M，所以：

$$P(至少一次碰撞)=1-\prod_{i=0}^{n-1}(1-i/M),\quad n\le M.$$

| 同名实例数n | 至少一次ID碰撞的概率 |
| --- | --- |
| 100 | .00033494，约.03349% |
| 1,000 | .03323981，约3.324% |
| 5,000 | .57081766，约57.08% |

这是生日问题的理论分布，使用60位Decimal乘积和log1p/expm1形式交叉核对，不是实际运行5000个代理的观测频率。n>M时必有重复；n很小时也不是概率严格为零。

## 重置同一随机流还会打破独立假设

本地先random.seed(0)，创建名为solver的实例；再重置相同种子，创建第二个solver。原random_id与原类得到两个不同对象，repr却都是 `solver 0UAq`。将第二个的Info交给第一个，原generate_prompt实际附上了yourself标记。

这个确定性构造说明，不能把表中独立均匀概率无条件用于有重置或共享状态的流程；它不是作者实验中碰撞频率的估计，也不意味着身份标记本身构成权限系统。

若要求同一运行内严格不重复，可以使用受控的递增身份或注册并检查碰撞的分配器；跨运行还需要运行命名空间。消息应保存明确的运行/实例身份，把可读名字作为展示字段。仅把随机串加长能降概率，但不能替代唯一性不变量及状态协议。

练习：两个实例的ID相同、agent_name分别为critic和solver，原repr一定相同吗？答案：不同；应按真正被比较的完整身份定义冲突，不能混淆ID空间与带名字的消息归属键。
