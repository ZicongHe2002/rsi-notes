# 自动设计代理时，怎样把搜索与运行预算算清楚

一个代理最后答题只调用一次模型，不代表得到这个代理只花了一次调用。自动设计会消耗候选生成、反思、调试和验证预算。比较方法时若只保留胜出者的运行成本，就会把得到它的成本从账本中删掉。

本文按 ADAS 作者仓库的固定 MMLU 实现说明成本从哪里产生，再给出自行构造的预算算例。Codex 辅助整理，未运行搜索或测量 API 账单；代码默认值不当作论文实验的实际配置。

## 先声明比较的是哪个问题

有两种不同的比较：一种关心从零开始、在给定总预算内能得到多好的系统；另一种关心一个已经设计完成的系统，部署后每道题的成本和质量。两种问题都可以研究，但必须分别列账。

记设计阶段成本为 $C_{\mathrm{build}}$，部署 $N$ 次的平均单次成本为 $c_{\mathrm{run}}$。在忽略规模变化、缓存和价格变化的简化假设下：

$$
C_{\mathrm{total}}(N)=C_{\mathrm{build}}+N c_{\mathrm{run}}.
$$

独立最终测试的费用单独登记；若计入总预算，应对所有方法采用一致口径。没有完成搜索成本测量时，可以报告部署成本，但应同时标出搜索成本缺失，不能将其默认为零。

## 从 ADAS 的控制流找到各项成本

作者仓库 `_mmlu/search.py` 的 `search` 会先评价初始 archive 中尚无 fitness 的设计，随后按 generation 生成新设计。一个没有异常的候选生成路径包含一次初始生成和两次反思调用；因此默认的 `n_generation=30` 不能解释为总共30次模型调用。

候选代码通过 `evaluate_forward_fn` 在验证题上运行。验证失败还可能触发调试和重新评价；一个候选的 `forward` 又可以调用多个 `LLMAgentBase`。最终的 `evaluate` 会遍历 archive，对各设计记录 `test_fitness`。这些层次应分开统计。

| 成本项 | 在所核对实现中的位置 | 应记录的量 |
| --- | --- | --- |
| 初始设计评价 | `search` 开头评价已有 archive | 设计数量、题数、重复次数、每题内部调用 |
| 候选生成与反思 | `get_json_response_from_gpt_reflect` | 每次请求模型、输入/输出token、失败与重试 |
| 候选调试 | `debug_max` 控制的循环 | 修复请求及已发生的评价成本，包括最终丢弃者 |
| 候选验证 | `evaluate_forward_fn` 的搜索分支 | 实际候选数、独立题数、重复次数、内部代理调用 |
| 最终测试 | `evaluate` 与非搜索分支 | 被测试设计数、测试题数及重复次数 |
| 部署运行 | 冻结设计后接受新任务 | 每题token、工具开销、时延与质量 |

代码在同一次固定洗牌后，用前 `valid_size` 个样本作验证，后面一段作测试。所核对的默认值为128道验证题、800道测试题，`n_repreat=1`。假设数据足够且不发生额外调用，仅一个候选的一次验证就包含128次 `forward` 执行；若重复次数改为2，则为256次，不能把候选数当作调用数。重复同一题也不能当作新增了独立题目。

脚本里关于费用的计算行处于注释中，不能把它当作完整账单。实际费用还取决于每次调用的模型、输入输出长度、重试及价格；最大并发48也不是总调用数48。并发主要改变调度和时延，不能抹去已完成请求的费用。

## 一个能完整复算的摊销例子

以下数字是抽象成本单位，不是美元、token实测或 ADAS 论文数据。设方法A搜索花600单位，冻结后每题1单位；基线B没有额外搜索成本，每题3单位，二者最终独立测试成本另列，质量也需另行核对。

两者成本相等时 $600+N=3N$，所以 $N=300$。在100题规模，A花700、B花300；在1000题规模，A花1600、B花3000。A只有在超过300题后才在这组假设下更便宜，不能只看“每题1对3”就宣布任何规模都省钱。

若A的单题运行成本反而为4，而B仍为3，则 $600+4N>3N$ 对所有非负 $N$ 成立，不存在仅靠扩大部署量就省成本的交点。可能仍有质量收益，但那是成本与质量的权衡，不能改称为成本优势。

## 公平比较需要同时固定什么

从零设计的比较应给每种方法同一总预算上限，并记录失败候选和调试成本。部署比较则冻结候选及其所见信息，在同一未见任务分布上列出质量、费用和时延，明确设计成本是否摊销、摊销到多少题。模型身份、工具权限、上下文和采样次数都可能影响结果，不能只匹配最后输出的长度。

该实现会测试 archive 中多个设计。若随后依据这些测试成绩继续选设计，这批题便参与了选择；`test_fitness` 这个字段名本身不保证它仍是独立最终证据。需要冻结选择，或另留最终未见评价。本文不据代码文件推断作者实际采用了哪一种后续报告流程。

练习：搜索成本240，A每题2，B每题5，在50题和100题规模分别怎样比较？

答案：相等点为 $240/(5-2)=80$ 题。50题时A为340、B为250；100题时A为440、B为500。尚需确认相同质量要求下这些成本是否成立。
