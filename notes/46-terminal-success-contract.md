# 环境说done，什么时候才能把它记成任务成功

交互结束与目标达成可能是两个事件。环境也可能因为超时、耗尽行动或不可恢复错误而结束。只有核对当前环境版本的契约后，才能把终止标记直接当作成功标记；变量或日志字段叫success不足以建立这个等价关系。

## 固定Reflexion路径实际检查了什么

`alfworld_run`调用环境后，把`info['won'][0]`读入局部变量`reward`，把返回的`done[0]`读入`done`。随后若`done`为真，就返回`(env_history,True)`；该判断位置没有同时检查`reward`。历史耗尽或达到循环上限则返回False。

下面只审计这个包装分支，以假环境提供一条观察；表中组合是否会在真实ALFWorld版本出现，仍需查环境契约：

| 假环境done | 假环境won | 本分支是否返回True | 与won一致吗 |
| --- | --- | --- | --- |
| 真 | 真 | 是 | 是 |
| 真 | 假 | 是 | 否 |
| 假 | 真 | 不在done分支返回True | 此处尚不能断言 |
| 假 | 假 | 不在done分支返回True | 此处尚不能断言 |

若要把该True理解为目标成功，至少需要当前路径可达的终止状态满足`done ⇒ won`。如果环境契约本来保证这一点，两个变量在该路径没有冲突；不能仅凭本表的假输入反例，宣称作者真实实验存在误计。若契约允许“未赢但终止”，则必须区分这些终止原因。

## 完整账本怎样避免名称误导

构造100条结束时刻记录：80条done真且won真，10条done真但won假，10条因外部步数上限退出而won假。若前90条都被done分支记成True，会报告90%；按won的目标成功只有80%。这是一个明确允许第二类终止的假环境账本，不是ALFWorld测量值。

真正复核时要固定环境包版本、配置、包装器和成功定义，保存每条终止原因与原始字段；再验证是否存在`done真、won假`的可达记录。只看最终ACCURACY无法识别差异来源，观察到没有冲突也不证明所有版本或配置都保证等价。

更换环境时，应同时复核成功映射与停止规则。复制代理外层代码，却继续沿用旧环境关于done的含义，可能改变评价事件。反过来，把所有未在done分支返回True的情况都称为确定失败，也需要看后续步骤和预算，而不是只截取一行代码。

练习：某环境明文规定done当且仅当won，另外超时通过单独的truncated字段返回且不进入done分支。本表的done真/won假反例能否证明该环境被高估？答案：不能，该组合在给定契约下不可达；仍需核对外层是否正确处理truncated与预算退出。
