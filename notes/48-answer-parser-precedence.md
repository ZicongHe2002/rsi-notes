# 答案文本中出现多个选项时，解析器到底选了谁

报告的正确率同时取决于代理输出和把输出映射为选项的规则。若解析器按固定字母顺序查找子串，它可能选中推理中被否定的选项，而不是文本明确表达的结论。比较两个代理时，也要固定这层映射。

## 固定分支的优先顺序

ADAS固定MMLU路径先接受完全等于A/B/C/D之一的字符串；否则依次查找`'A)'`、`'B)'`、`'C)'`、`'D)'`，命中第一个条件就决定选项。这里的“第一个”是代码中条件的字母顺序，不是子串在文本中最先出现的位置，也不识别“错误”“排除”等语义。

对以下构造字符串，原解析循环的结果为：

| 返回字符串 | 解析结果 | 原因 |
| --- | --- | --- |
| `B` | B | 精确匹配 |
| `B) correct; A) is wrong` | A | A)条件先于B)判断 |
| `C) correct; B) is wrong` | B | B)条件先于C)判断 |
| ` B ` | 解析失败并计0 | 没有去除两侧空格，也没有带括号子串 |
| `b` | 解析失败并计0 | 没有在该路径转为大写 |
| `A) or D)` | A | 多选没有被单独拒绝 |

若上述六条的独立正确标签都构造为B，得到的0/1结果是`[1,0,1,0,0,0]`，总分2/6。其中第三条恰好被解析成正确标签，不代表它表达的结论正确。这个例子不能用来估计真实模型的误差率；它只核对当前字符串映射。

## 严格与宽松解析回答不同问题

严格契约可以要求返回值恰好属于四个枚举值，格式偏差单独记无效。若为了容忍空格而规定先strip，必须把规范化步骤固定下来，并说明大小写、标点、多选和解释文字的处理方式。允许从任意长段落里找字母，会引入更多歧义；一次命中不等于歧义已消除。

同一批原始输出可用两套预先规定的规则做敏感性核对，但不能看哪套能让新代理分数更高后，再将它称作唯一评价规则。尤其是自我改进系统，若新版本只把答案写得更容易被当前解析器接受，提升可能主要来自格式兼容；这仍可有实际价值，但应和知识或推理改善区分。

## 最小可核对账本

逐条保存任务ID、原始返回值及类型、规范化结果、解析状态、最终选项、独立正确标签和解析器版本。无效输出可以在总准确率里记0，同时另报有效输出比例；不能从主分母中删去失败记录后仍把结果称为全部任务的准确率。

练习：字符串`'D) is correct; A) is not'`在本分支会得到什么？答案：A；因为代码先检查A)是否存在。文本里D)出现得更早不会改变条件顺序。
